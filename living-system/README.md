## Purpose

This directory defines a source-first, appendable publication that can be rendered as:

1. a navigable, hyperlinked PDF with dynamic table of contents, bookmarks, index, margin annotations, metadata and embedded source artifacts;
2. a browser-based editorial companion using HTMX 4.0.2 and structured Markdown/data blocks;
3. a versioned source ledger whose append-only JSONL history is the canonical content record.

The PDF is a durable publication snapshot. The JSONL ledger and source files are the editable canonical record. A new PDF is reproducibly rebuilt from the full ledger after each accepted append; bytes are not blindly concatenated to an existing PDF.

## Source-derived design requirements

The uploaded architecture review describes an editable notebook, state assimilation, generation lineage, parent/content/runtime hashes, append-only local VFS ledger, import/export, and explicit capability states. It also cautions that visible status must not imply a subsystem is active without evidence. The Memory Fabric material defines the progression **quarantine → provenance → graph → promotion → ledger**. The project’s device architecture separates runtime supervision, telemetry, plugins, device registry, dashboard, AI gateway, and state storage.

This publication adopts those concepts as content governance and provenance controls. It does not claim to implement a distributed VFS, device-control plane, or autonomous agent network.

## PDF capabilities and limits

The generated PDF contains real PDF hyperlinks, internal destinations, bookmarks, metadata, a printed index, margin notes, and embedded source files. The companion HTML file is attached to the PDF and linked from its cover. A PDF viewer does not become a browser: embedded HTMX/JavaScript is not assumed to execute inside the PDF page. Readers open the attached or linked editorial companion in a browser.

PDF attachments are supported by the PDF format, but viewer handling varies. Therefore, the canonical sources are also published as ordinary repository files.

## HTMX 4.0

The editorial companion pins `htmx.org@4.0.2`. The official HTMX 4 announcement states that 4.0.0 was released on 2026-08-28; the 4.x line remains separately versioned from the default 2.x CDN alias. The page uses an explicit 4.0.2 URL rather than an unversioned alias. The 4.x inheritance and event changes are accounted for by avoiding implicit inherited request attributes in this prototype.

## Build

Requirements: Python 3.11+, Pandoc, pdfLaTeX, and the Python package `pypdf`.

```bash
python -m pip install pypdf
python living-system/tools/build.py
```

The script validates the append-only JSONL ledger, generates LaTeX from Markdown/data blocks, compiles the manuscript, attaches the HTML/editorial and source artifacts, and writes a SHA-256 build manifest. It fails visibly if required build tools or inputs are missing.

## Append workflow

1. Open `editorial/index.html` from the GitHub Pages site or a local web server.
2. Load the current block ledger.
3. Add a Markdown or LaTeX-math block with a unique ID, margin annotation, and index terms.
4. Export the complete JSONL ledger.
5. Review the proposed addition and commit it as a new source revision. Do not overwrite prior releases.
6. Run the PDF build. The new PDF is a complete rendering of the complete ledger and carries the exact source files used to produce it.

The browser editor's local storage is a convenience, not the canonical shared ledger. Git history is the revision record.
