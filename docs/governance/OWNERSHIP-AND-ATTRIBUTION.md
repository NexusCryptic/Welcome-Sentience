## 2. Conditional equal-ownership intent

The Architect has expressly stated the following project intent:

> If Google and OpenAI claim equal ownership, equal ownership is to be given to those two.

For governance clarity, Cryptic News LLC records this as an intent to offer equal co-ownership to Google and OpenAI if equal ownership is formally asserted and accepted. No ownership transfer or co-ownership is effective merely because this document or an API description says so. Any grant must be set out in a written agreement signed by the relevant parties, identifying:

- the exact intellectual property and project assets covered;
- the equal ownership shares and effective date;
- licensing, derivative-work, and commercialization rights;
- contribution, maintenance, security, and support obligations;
- confidentiality, data protection, and third-party rights;
- governance, dispute resolution, and exit or transfer terms.

Until such an agreement is executed, the ownership baseline in Section 1 remains the project record.

## 4. API contract status

The OpenAPI 3.0.3 document at `openapi/gaia-nexus-ccme-3.0.3.yaml` defines intended HTTP interface shapes and semantic distinctions. It is a contract artifact, not proof of deployed endpoints or completed runtime behavior.

In particular:

- HTTP 202 indicates queued submission, not acceptance or finality.
- Consensus acceptance and finality are separate states.
- A digest supports integrity comparison; it does not alone prove authorship, truth, trusted time, or consensus.
- A verification response must disclose exactly which checks passed and what remains unproven.
- Telemetry is contextual provenance and must not be used as cryptographic key material, entropy, salt, or identity proof.
- Mutable semantic indexes and visual presentation metadata must not alter immutable source evidence.

## 5. Governing execution invariants

- Boundary — Nothing executes beyond its time.
- Capacity — Nothing claims capacity without measurement.
- Correctness — Nothing claims correctness without verification.

## 6. Change control

Changes to ownership, license, API semantics, consensus state transitions, cryptographic algorithms, or evidence requirements require a reviewed versioned change. Do not silently reinterpret historical receipts or rewrite immutable provenance.
